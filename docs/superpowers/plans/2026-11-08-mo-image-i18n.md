# dsh-mo-image 客户端多语言实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法跟踪进度。

**目标：** 让插件设置页与右下角生图模型选择器跟随 DSH 的 8 种内置语言（zh、en、ja、es、fr、de、ru、pt），全部前端文案（含 aria-label 与用户可见报错）走 `ctx.locale`。

**架构：** `locale/messages.csv` 是唯一文案源（每列一种语言）；`scripts/build-locales.mjs` 校验 CSV 并把 8 份字典生成到 `lib/client.js` 的一对标记之间。客户端 `apply` 通过 `ctx.locale.register('dsh-mo-image', dicts)` 注册，并把 `ctx.locale.bind(ns)` 注入两个插槽组件；DSH 切换语言时插槽会重绘，文案立即更新。

**技术栈：** 原生 ESM、Node `node:test`、DSH client locale 服务、手写 CSV 解析器（RFC 4180）。

**规格：** 本计划（用户需求：设置页 + 模型选择器 + 用户可见报错本地化；提示词与工具描述不动）。

## 全局约束

- 只支持 DSH 内置的 8 个 locale：`zh`、`en`、`ja`、`es`、`fr`、`de`、`ru`、`pt`；`zh` 与 `en` 为必填基线。
- 不改 `lib/index.js`、`lib/prompt-profiles.js`、`skills/**`、工具描述与系统提示词。
- 文案要像母语产品文案，不做逐字直译；技术名词（API、URL、ID、模型 ID、OpenAI Images、HD）保留。
- 生成块只允许由 `npm run build:locales` 写入；`npm run check:locales` 必须在 CI/测试中保持同步。
- 不引入新的运行时依赖。

## 审查重点

| 输入/条件 | 应得行为 | 对应测试 |
|---|---|---|
| 用户切换到 `ja`/`ru` 等非中英语言 | 设置页和选择器立即显示该语言，不残留中文 | `client-i18n`：切 locale 后 label 与 t 输出变化 |
| CSV 新增一列或改一行文案 | `build:locales` 可重新生成；未重新生成时测试失败 | `locales`：生成块与 CSV 同步 |
| 某语言漏翻一个 key | 测试失败并指明 key/language | `locales`：每语言 key 集合一致 |
| 某语言漏掉 `{count}` 占位符 | 测试失败 | `locales`：占位符集合一致 |
| 插件在无 locale 服务的测试/宿主环境 | 回退到中文，不抛异常 | 现有 client 单测（ctx 不含 locale） |
