# 更新日志（Release notes）

发版时 `push.js` 会让你从这里挑一份 `.md` 作为 GitHub Release 的正文——那段正文就是用户在「有可用更新」对话框里看到的内容。

约定：

- 文件名跟 tag 走：tag 是 `v0.9.0-rc1`，文件就叫 `v0.9.0-rc1.md`（脚本会自动把它排在第一位并推荐）。
- 内容用普通 markdown，只用到标题、列表、段落；对话框按这些块渲染，不执行 HTML。
- 选中后脚本会把它提交进仓库（`docs: add release notes for <tag>`），因为发版要求工作区干净。
- 不想写也行：选 `n` 就不附带，Release 正文由上次 tag 以来的提交标题自动生成。
- `-a`（alpha）/ `-b`（beta）会被标成 GitHub 的 prerelease，已装用户不会收到更新提示；`-rc` 与正式版会。

模板：

```markdown
### 新功能

- 一句话说清用户能做什么

### 修复

- 一句话说清修了什么

### 升级注意

- 需要用户动手的地方（没有就删掉这一节）
```

已经发过的日志不用删，留着当历史。
