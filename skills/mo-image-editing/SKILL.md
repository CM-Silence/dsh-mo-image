# 图片编辑与版本迭代

## 硬性约束（先读）

- 只负责把编辑提示词和参考图交给生图模型，不替用户判断图片好坏。
- 本会话首次生图或改图前调用 `mo_image_settings`。之后直接调用 `mo_image_edit`，由工具通过 `needsSettings` 返回变更或校准配置。使用返回的完整设置，或在 `baseRevision` 上应用 `changes`、清除 `removed`，然后发起新调用。应用增量时找不到基线才用 `refresh:true` 读取完整配置。
- 自动模型使用 `editModelIndexes` 从 `models` 选择，也可以省略 `model` 使用首个可改图的候选。需要具体尺寸、质量或参数时，传候选的模型 ID 查询。
- ComfyUI 若返回 `referenceImages`，按其中的编号、用途和数量传 `images`。自动模式下，若所选候选位于 `referenceModelIndexes`，在缺少该候选详情或 `referenceRevision` 改变时查询一次。图片用途有歧义时向用户确认。
- `model` 不用传：非 Auto 时用选择器里的模型，传别的值会被拒绝；Auto 必须从当前列表里选一个。
- 图片返回即交付：最终回复只输出工具给的图片行；不评价画质、不描述画面。除非用户明确要求看图，否则不要打开或读取图片。
- 只用选择器里的提供商和模型：不要自行切换，也不要用本地生图、建模/Blender、脚本绘图替代。
- 收到「生图配置不匹配（未提交）」时，用 `mo_image_settings({"refresh":true})` 重读完整配置，纠正参数后只重试一次。仍失败或遇到其他错误时原样报错。沿用用户选定的提供商和模型。

优化开启时，在提示词里**说清改什么、保留什么**。复用上下文已有的写法和合适的成稿。优化关闭时，prompt 只写用户原话或做最低限度整理；用户明确要求优化时才改写。工作流有入口编号时按编号传参考图，其余情况沿用用户指定的顺序。

## 一、编辑公式

`动作动词 + 目标元素 + 期望的变化 + 风格细节`

五类高权重约束词：

| 约束 | 用法 | 示例 |
|---|---|---|
| 保持 | 锁定不想被改的部分 | 保持人物脸型、发型、姿势和背景不变 |
| 修改 | 改变指定元素的属性 | 把发色改成银白色，保持画风和设计特征不变 |
| 添加 | 向画面新增元素 | 给手持相机上添加一只小黄猫，画风保持一致 |
| 删除 | 移除指定内容 | 去掉长筒袜、翅膀和地上的布料 |
| 替换 | 用另一张图的元素替换 | 参考图2的轮子设计，把图1摩托后轮替换成图2的轮子 |

补充：`使...` 用于整体氛围，`风格` 用于整体转绘（“转成 UE5 写实风”）。

## 二、按模型编辑

| 模型族 | 编辑写法 | 注意 |
|---|---|---|
| GPT-Image | 只改 X，其余保持不变；每轮重复保留清单 | 多图按图1/图2编号；文字用引号；无 negative |
| Nano Banana / Gemini Image | 强动词开头，明确保留项，可描述蒙版区域 | 正向描述，不用否定句；支持多图融合 |
| Seedream | 增加/删除/替换/修改 + 对象 + 变化 | 避免“它/那个”；强调其余不变；支持图1/图2 |
| Qwen-Image | 按图1/图2说明关系，只改指定区域 | 支持 negative prompt；文字和版式要保留 |
| FLUX Kontext | 改什么 + 保持什么 | 不支持的排除项写成正面描述 |
| Stable Diffusion / Stability | 说明保留区域和修改区域 | 支持 negative；局部重绘优先用蒙版 |
| DALL·E 3 / 通义万相 | 不建议做参考图编辑 | 换 GPT-Image、Seedream、Nano Banana 等 |

示例：

```text
Use Image 1 as the base. Replace only the background with a soft light-gray seamless studio backdrop. Keep the product, its position, scale, label text, reflections, and the original lighting completely unchanged. Match the new background's shadow direction to the product, no extra objects, no text, no watermark.
```

```text
把图1中人物的外套替换成图2的米色风衣，保持人物脸型、发型、姿势、内搭和背景不变，风衣的材质和褶皱要自然，光影与图1一致。
```

## 三、常用模板

### 局部修改

```text
图1是<原图说明>。只把<目标元素>改成<变化>，保持<主体/脸/发型/姿势/构图/背景/文字/光线>不变。不要新增其他元素，不要改变画风。
```

### 换背景 / 换装

```text
图1是<主体>，图2是<服装/材质参考>。只把背景换成<新背景>；或让人物穿上图2的<服装>，只替换<部位>。保持主体位置、比例、边缘、投影、脸型、发型、姿势和原图光线一致；材质和褶皱自然，不要像贴上去的。
```

### 多图融合 / 风格迁移

```text
图1：人物；图2：服装；图3：场景；图4：风格参考。用图1的人物、图2的服装、图3的场景，按图4的风格和色彩重绘。保持人物身份和姿势，元素自然融合，光影统一。
```

### 文字 / Logo 修改

```text
只把图1中的文字“<原文>”改成“<新文字>”，保持字体、字号、颜色、位置、倾斜和背景不变。文字拼写必须准确，不新增其他文字，不改动图形和排版。
```

## 四、自检清单

1. 每张参考图是什么，是否按图1/图2写清？
2. 是否只改一个具体点，保留项列全了吗（身份、脸、发型、姿势、构图、文字、光线、背景）？
3. 是否用了“它/那个”这类模糊指代？新元素的光影、透视、材质是否与原图一致？
4. 文字加了引号、拼写准确？当前模型支持参考图编辑和 negative prompt 吗？

## 五、重绘幅度

只有当 `mo_image_settings` 返回了 `params` 且其中有重绘幅度（`denoise` 或 `denoising_strength`）时才适用；优化开启时按需求主动调：

| 用户想要 | 重绘幅度 |
|---|---|
| 只改一个小地方，构图和主体都要保住 | 0.2–0.35 |
| 换背景、换风格，但保留大结构 | 0.5–0.6 |
| 大改、几乎重画 | 0.65–0.8 |

改完告诉用户调了多少、为什么；没暴露就留空用默认值。步数和提示词强度见 `mo-image-generation` 的参数调优。

## 六、调用

- 改图前确认配置最新（同「硬性约束」）；`images` 是 1–16 张本地绝对路径或 http(s) URL，顺序对应图1/图2，不能错。
- `prompt`：按当前模型写好的最终编辑提示词；`negative_prompt`：只在当前模型支持时传。
- 选择器把尺寸或质量设为自动时，可传相应的 `size` 或 `quality`，质量取值见 `qualityOptions`。固定时省略相应参数。
- 编辑可能较慢，工具超时 360s，不要重复提交同一请求；返回 Markdown 图片行，原样复制到最终回复。
